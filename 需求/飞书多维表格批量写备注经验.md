# 飞书多维表格（Bitable）批量写入「备注」文本经验

> 场景：用 chrome-devtools MCP 控制已登录的飞书浏览器，给一批 BUG 记录的「备注」文本字段批量填入验收说明，并确认真实落库。
> 配套脚本：`scripts/feishu-fill-remarks.js`
> 相关文档：《飞书多维表格图文抓取经验.md》（读）、《飞书多维表格批量改状态经验.md》（改单选状态）

---

## 1. 一句话结论

> **批量写「备注」文本，优先在表格网格里直接编辑备注列：用 `BitableTestTool` 定位单元格 → 双击进入编辑器 → `insertText` 写入 → 点击同行的「BUG状态」列提交。可一次循环处理多条，比逐条打开记录弹窗快得多。不要依赖 `setCellValue` / `setPartialCell`（只改本地），也不要点「模块」字段提交（会误开字段配置面板）。**

## 3. 为什么不能走「捷径」

| 方案 | 结果 | 说明 |
|------|------|------|
| 手拼 `batch_update` 等 HTTP 写接口 | ❌ 404 / 高风险 | 未找到稳定公开写接口；OT 协同需正确 rev 与操作序列。 |
| `table.setCellValue` / `setPartialCell` | ❌ 不落库 | 本地内存会变，`getRev()` 不涨，服务端回读仍为空。 |
| 记录弹窗 + `type_text` + 点 BUG名称 | ✅ 可靠但慢 | 每条需 `location.assign(?record=...)` 等弹窗加载，约 10～20 秒/条。 |
| 网格备注列编辑 + 点 BUG状态 提交 | ✅ **推荐** | 同页循环，约 1～2 秒/条；9 条可在一次 `evaluate_script` 内完成。 |
| 网格备注列 + Tab / Enter / Ctrl+Enter 提交 | ❌ 不落库 | 仅本地显示，服务端 `fldcgLPCQd` 仍为空。 |
| 点「模块」字段提交 | ❌ 误操作 | 会打开字段配置面板，备注未必保存。 |

---

## 4. 推荐流程（批量写备注）

```
1. 打开表格并确认已登录（chrome-devtools MCP 的 isolated 浏览器需用户先登录）
2. 等待 `window.BitableTestTool` 可用
3. 按 BUG名称 关键词匹配行号（rowIdx），勿长期依赖固定行号（筛选/滚动会变）
4. 对每条记录：
   a. showCell(rowIdx, 6) 滚动备注列入视区
   b. 单击 + 双击单元格，出现 contenteditable 编辑器
   c. selectAll → insertText 写入验收说明
   d. dispatch InputEvent('input')
   e. showCell(rowIdx, 0) 后单击 BUG状态 列 → 触发提交
   f. sleep 1～1.5s 再处理下一条
5. 全部写完后，用 records 接口 gzip 解码回读，按 recordId 校验备注非空
6. 对比 tableRev / getRemoteRev() 是否上涨
```

## 5. 核心代码（浏览器 `evaluate_script`）

### 5.1 单条写入备注

```js
async function fillRemark(rowIdx, text) {
  const tt = window.BitableTestTool;
  const sleep = ms => new Promise(r => setTimeout(r, ms));

  tt.showCell(rowIdx, 6);
  await sleep(400);
  const rect = tt.getCellRect(rowIdx, 6);
  const canvas = document.querySelector('canvas');
  const cr = canvas.getBoundingClientRect();
  const cx = cr.left + rect.x + rect.width / 2;
  const cy = cr.top + rect.y + rect.height / 2;
  const tel = document.elementFromPoint(cx, cy) || canvas;

  tel.dispatchEvent(new MouseEvent('click', { bubbles: true, clientX: cx, clientY: cy, view: window }));
  await sleep(200);
  tel.dispatchEvent(new MouseEvent('dblclick', { bubbles: true, clientX: cx, clientY: cy, detail: 2, view: window }));
  await sleep(400);

  const ed = document.querySelector('[contenteditable=true]');
  if (!ed) return { ok: false, reason: 'no editor' };
  ed.focus();
  document.execCommand('selectAll', false, null);
  document.execCommand('insertText', false, text);
  ed.dispatchEvent(new InputEvent('input', { bubbles: true }));
  await sleep(200);

  // 点击 BUG状态列提交（col 0），不要点「模块」
  tt.showCell(rowIdx, 0);
  await sleep(300);
  const rect0 = tt.getCellRect(rowIdx, 0);
  const tel0 = document.elementFromPoint(
    cr.left + rect0.x + rect0.width / 2,
    cr.top + rect0.y + rect0.height / 2,
  ) || canvas;
  tel0.dispatchEvent(new MouseEvent('click', { bubbles: true, view: window }));
  await sleep(1200);
  return { ok: true };
}
```

### 5.2 按关键词找行（匹配 BUG名称）

```js
function findRowByKeyword(keyword) {
  const tt = window.BitableTestTool;
  for (let i = 0; i < 60; i++) {
    const n = tt.getCell(i, 1)?.[0]?.text || '';
    if (n.includes(keyword)) return i;
  }
  // 兜底：在任意列搜关键词（例如 BUG名称 被误写入时）
  for (let i = 0; i < 60; i++) {
    for (let c = 0; c < 8; c++) {
      const s = JSON.stringify(tt.getCell(i, c) || '');
      if (s.includes(keyword)) return i;
    }
  }
  return -1;
}
```

### 5.3 服务端回读校验（gzip + base64）

```js
async function verifyRemarks(recordIds) {
  const token = 'NbhqbK5OfahIaOsA7nAc3uaonXb';
  const tableId = 'tblt71WCcW4LUngs';
  const url = `/space/api/v1/bitable/${token}/records?tableId=${tableId}&recordIds=${recordIds.join(',')}`;
  const j = await (await fetch(url, { credentials: 'include' })).json();
  const bin = Uint8Array.from(atob(j.data.records), c => c.charCodeAt(0));
  const ds = new DecompressionStream('gzip');
  const text = await new Response(new Blob([bin]).stream().pipeThrough(ds)).text();
  const parsed = JSON.parse(text);
  return recordIds.map(id => ({
    id,
    saved: !!(parsed.recordMap?.[id]?.fldcgLPCQd?.value?.[0]?.text?.trim()),
    preview: (parsed.recordMap?.[id]?.fldcgLPCQd?.value || [])
      .map(x => x.text).join('').trim().slice(0, 30),
  }));
}
```

> 注意：`recordMap[id].fldcgLPCQd` 是字段 ID 直挂结构，不是 `fields` 嵌套。详见《飞书多维表格图文抓取经验.md》。

## 6. 改单选状态（待处理 → 待验收）补充

备注写完后若还需改状态，见《飞书多维表格批量改状态经验.md》。本次额外踩坑：

- 下拉里必须点 **`li.b-select-option`** 且文字为「待验收」，不要点父级或「已修复」。
- 下拉 DOM 顺序可能是：待验收、已修复、待处理；用 `textContent.trim() === '待验收'` 精确匹配。
- **BUG状态**（col 0）与 **BUG状态1**（col 3）都要改成待验收时，分别对两列执行 `setSelect(row, col, optId)`。

## 7. 记录弹窗写法（备用，较慢）

当网格备注列不可见（列被隐藏）或批量脚本报错时，可退回记录详情弹窗：

```
1. location.assign('...wiki/...?table=tblt71WCcW4LUngs&record={recordId}')
2. 轮询直到 dialog 内同时出现「BUG名称」「备注」
3. 点击备注区 contenteditable → MCP type_text 输入
4. 点击「BUG名称」标签失焦保存（不要点「模块」）
5. 服务端回读确认
```

`?record=` 参数有时会被重定向剥掉，弹窗只显示标题不加载正文时需关闭重试或改用网格法。

## 8. 踩坑清单

1. **行号不稳定**：筛选、滚动、他人改表后 `rowIdx` 会变；用 **BUG名称关键词** 或 **recordId** 定位，最终校验必须用 recordId。
2. **提交方式**：备注文本列必须靠「点击另一可编辑列」提交；Tab/Enter 在网格里通常不落库。
3. **勿点模块**：点「模块」会打开单选字段配置，备注可能未保存。
4. **本地假象**：`getCell` 或弹窗里已有文字，但 `records` 接口 `fldcgLPCQd` 为空 = 未落库。
5. **tableRev 上涨**：批量写 9 条备注 `tableRev` 从 518 → 526，可作为落库旁证。
6. **chrome-devtools MCP**：配置 `--isolated` 时需用户在该浏览器窗口登录飞书；写操作前 `shouldTableEditable({ tableId })` 应为 `true`。
7. **与改状态文档一致**：`setCellValue` 永不作为写库手段；单选状态仍走 UI 下拉通道。

## 9. 写 vs 读 vs 改状态 速记

| | 读备注/记录 | 写备注（推荐） | 改单选状态 |
|--|-------------|----------------|------------|
| 入口 | `records` 接口 + gzip 解码 | 网格 col 6 编辑 + col 0 点击提交 | `BitableTestTool` + 下拉 `li.b-select-option` |
| 校验 | `recordMap[id].fldcgLPCQd` | 同左 + `tableRev` 上涨 | `optId` 回读 + `getRemoteRev()` |
| 批量 | 一次 fetch 多条 recordIds | 同页 `for` 循环，无需逐条导航 | 逐行改 col，间隔 300～400ms |
| 主要风险 | 字段结构是 recordMap 直挂 | 误点模块、Tab 不落库 | 误点「已修复」、行号错位 |
