# AI 助手真实对话系统 - 测试指南

## 🎯 测试目标

验证 AI 助手页面从固定回复模式改造为真实 AI 对话系统后的功能完整性、用户体验和性能表现。

---

## 📋 测试清单

### 1. 基础功能测试

#### 1.1 页面加载
- [ ] 页面正常打开，无白屏
- [ ] 吉祥物头像和问候语正常显示
- [ ] 礼赠场景卡片正确渲染（4个）
- [ ] 底部输入框和快捷按钮正常显示

#### 1.2 礼赠场景选择
- [ ] 点击"送爱人/恋人" → 用户消息显示在右侧
- [ ] AI 回复在左侧出现，有头像
- [ ] 显示"正在输入"三点动画（约0.5秒）
- [ ] AI 回复逐字符流式显示
- [ ] 风格选择网格正常出现

#### 1.3 风格选择
- [ ] 风格卡片为**单选模式**（只能选一个）
- [ ] 选中风格后有视觉反馈
- [ ] 点击"确认选择" → 用户消息显示选择结果
- [ ] AI 回复 + 推荐卡同时出现
- [ ] 点击"随便看看" → 跳过风格选择

#### 1.4 智能推荐
- [ ] 推荐卡显示3个候选花型
- [ ] 主推荐图片正常显示
- [ ] 候选项点击可切换主推荐
- [ ] "换一批"按钮有 loading 状态
- [ ] 换一批后显示不同的花型

### 2. 对话逻辑测试

#### 2.1 流式返回
测试场景：选择"送爱人/恋人" → 选择"浪漫花卉"

**预期行为**:
1. 用户消息立即显示在右侧
2. AI 消息出现在左侧，先显示三点动画（~0.5秒）
3. 三点消失，文字逐字符显示（30ms/字符）
4. 滚动条自动跟随文字输出
5. 输出完成后状态变为 "done"

**检查点**:
- [ ] 三点动画流畅，无卡顿
- [ ] 文字输出速度自然（不太快也不太慢）
- [ ] 滚动跟随流畅，不抖动
- [ ] 输出期间不能发送新消息（按钮禁用）

#### 2.2 AI 回复质量
测试不同场景的回复是否个性化：

| 场景 | 风格 | 预期回复关键词 |
|------|------|---------------|
| 送爱人 | 浪漫花卉 | "温柔"、"甜蜜"、"浪漫" |
| 送闺蜜 | 运动活力 | "活力"、"清爽"、"运动" |
| 送长辈 | - | "品质"、"舒适"、"沉稳" |
| 送自己 | 简约纯色 | "百搭"、"质感"、"简约" |

**检查点**:
- [ ] AI 回复根据场景和风格变化
- [ ] 回复内容自然，不生硬
- [ ] 推荐理由合理

#### 2.3 上下文记忆
测试步骤：
1. 选择"送爱人/恋人"
2. 选择"浪漫花卉"
3. 手动输入："我想要粉色的"

**预期行为**:
- AI 回复应该结合之前的场景（送爱人）和风格（浪漫花卉）
- 推荐的花型应该偏向粉色+浪漫风格

**检查点**:
- [ ] AI 记住之前的选择
- [ ] 新推荐基于累积上下文

### 3. 推荐算法测试

#### 3.1 匹配准确性

测试矩阵：

| 场景 | 风格 | 预期推荐包含 |
|------|------|-------------|
| 送爱人 | 浪漫花卉 | 花卉类、粉色系 |
| 送长辈 | 国潮纹样 | 仙鹤、回纹、祥云 |
| 送自己 | 简约纯色 | 几何纹样、纯色系 |
| 送闺蜜 | 运动活力 | 清爽图案、活力色 |

**检查点**:
- [ ] 推荐结果符合场景和风格
- [ ] 推荐理由逻辑合理
- [ ] 3个候选项都相关

#### 3.2 换一批功能
测试步骤：
1. 记录首次推荐的3个花型ID
2. 点击"换一批"
3. 对比新推荐的花型ID

**预期行为**:
- 新推荐不包含之前的3个花型
- 新推荐质量不下降（同样符合场景）
- 有 loading 状态提示

**检查点**:
- [ ] 换一批后显示不同花型
- [ ] 新推荐质量保持
- [ ] 有 loading 反馈

### 4. 交互流程测试

#### 4.1 页面跳转

| 起点 | 操作 | 目标页面 | 携带数据 |
|------|------|----------|----------|
| AI助手 | 推荐卡 → "袜版选择" | `/pages/upload/index` | 推荐图片URL |
| AI助手 | 推荐卡 → "去定制" | `/pages/editor/index` | AI提示词 |
| AI助手 | 推荐卡 → "一键下单" | `/pages/upload/index?from=ai` | 推荐图片URL |

**检查点**:
- [ ] "袜版选择"跳转到 upload 页面（不是 editor）
- [ ] upload 页面接收到推荐图片URL
- [ ] "去定制"跳转到 editor 页面
- [ ] editor 页面接收到 AI 提示词
- [ ] "一键下单"跳转到 upload 页面（带 from=ai 参数）

#### 4.2 快捷分类
测试步骤：
1. 点击底部"运动袜"按钮
2. 观察对话流

**预期行为**:
- 用户消息显示："想要运动袜"
- AI 回复包含运动相关推荐
- 推荐卡显示运动风格花型

**检查点**:
- [ ] 快捷按钮触发对话
- [ ] AI 理解分类意图
- [ ] 推荐结果匹配分类

#### 4.3 自由输入
测试输入：
- "我想要红色的袜子"
- "送给妈妈的礼物"
- "国潮风格"
- "简约一点的"

**检查点**:
- [ ] AI 能理解自由输入
- [ ] 回复相关且自然
- [ ] 推荐符合输入意图

### 5. 错误处理测试

#### 5.1 网络错误模拟
测试步骤：
1. 开启飞行模式或断网
2. 发送消息

**预期行为**:
- AI 消息显示错误状态
- 显示红色边框和错误提示
- 出现"重试"按钮

**检查点**:
- [ ] 错误状态正确显示
- [ ] 错误提示清晰
- [ ] 重试按钮可用

#### 5.2 重试功能
测试步骤：
1. 触发错误（断网）
2. 恢复网络
3. 点击"重试"按钮

**预期行为**:
- 移除错误消息
- 重新发送 AI 请求
- 正常显示流式回复

**检查点**:
- [ ] 重试成功执行
- [ ] 不重复添加用户消息
- [ ] 流式显示正常

#### 5.3 超时保护
测试步骤：
1. 触发慢网络（或等待超时）
2. 观察30秒后行为

**预期行为**:
- 30秒后流式输出自动停止
- 显示超时错误
- 可重试

**检查点**:
- [ ] 超时正确触发
- [ ] 不会无限等待
- [ ] 可恢复正常使用

### 6. 性能测试

#### 6.1 连续对话

**检查点**:
- [ ] 对话流畅，无卡顿

- [ ] 历史消息限制生效（最多10条）

测试步骤：
1. 触发长文本回复（选择复杂场景）
2. 观察流式输出

**检查点**:
- [ ] 长文本输出流畅
- [ ] 不掉帧
- [ ] 滚动跟随准确

#### 6.3 快速切换
测试步骤：
1. 快速连续点击礼赠场景
2. 快速点击"换一批"

**检查点**:
- [ ] 不出现并发错误
- [ ] 按钮正确禁用（处理中）
- [ ] 状态一致

### 8. 边界情况测试

#### 8.1 空输入
测试步骤：
1. 不输入任何内容，点击发送

**预期行为**:
- 不发送消息
- 无错误提示

**检查点**:
- [ ] 空输入被忽略
- [ ] 不产生空消息

#### 8.2 超长输入
测试步骤：
1. 输入200+字符的文本

**预期行为**:
- 消息正常发送
- 气泡宽度适配
- 文本自动换行

**检查点**:
- [ ] 长文本显示完整
- [ ] 布局不破坏
- [ ] 可正常滚动查看

#### 8.3 特殊字符
测试输入：
- Emoji: "我想要❤️图案的袜子"
- 符号: "简约 & 时尚"
- 换行: "想要\n粉色的\n袜子"

**检查点**:
- [ ] Emoji 正常显示
- [ ] 特殊字符不报错
- [ ] 换行正确处理

#### 8.4 无推荐结果
测试步骤：
1. 修改花型数据库为空（开发测试）
2. 触发推荐

**预期行为**:
- 显示兜底推荐
- 或显示友好提示

**检查点**:
- [ ] 不出现空白推荐卡
- [ ] 有降级方案

## 🔧 开发者调试技巧

### 查看 Console 日志
关键日志标记：
- `[AI Chat]`: 对话核心逻辑
- `[AI Stream]`: 流式输出
- `[AI Recommend]`: 推荐引擎

### 修改流式速度
在 `composables/useAiStream.ts` 修改：
```typescript
const charDelay = 30 // 改小 = 更快，改大 = 更慢
```

### 修改推荐算法权重
在 `composables/useAiRecommend.ts` 修改 `calculateScore` 函数的加分规则。

### 查看上下文状态
在浏览器 console 输入：
```javascript
// 查看对话历史
console.log(context.value.history)
// 查看当前场景
console.log(context.value.scene)
```
